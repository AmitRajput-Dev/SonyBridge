# Fixture provenance

The XM4 v1 payloads are cross-checked against two independently maintained community references:

- Gadgetbridge `27ed00aa4232eaa360172b78b35d2fb168c190f0`: `PayloadTypeV1.java` and `SonyProtocolImplV1.java`. This is the primary source for command IDs, subtypes, and payload layouts, including DSEE, auto power-off, EQ, ambient sound, battery, firmware, codec, and Speak-to-Chat.
- `tanat/sony-connect-osx` `1a68e3bee54778c2db92db6379fa24662537b1db`: `SonyPacket.swift` and `HeadphonesController.swift`. This is an XM4-specific independent source for frame escaping, checksum rules, strict frame length, and the core XM4 commands.

The exact frames were generated on 2026-08-24 with Ruby 3.4 from `generate_reference_goldens.rb`. That script is a clean-room transcription of the documented wire rules and pinned payload facts. Regenerate to a temporary file, diff every byte against `fixtures/xm4_v1_frames.golden`, and update this file when either reference revision changes.

The v2 multipoint payloads in `fixtures/ult900n_v2_multipoint.golden` (generated by the same script with the `ult900n_v2_multipoint` argument) are pinned from Gadgetbridge's ConnectTwoDevices feature as hardware-verified on the WH-ULT900N (ULT WEAR): commits `8cbc309346` ("WIP add ConnectTwoDevices feature"), `e8520865f3` ("fix: setting Connect Two Devices"), and `5d7b37d1b7` ("fix read Connect Two Devices"), all 2026-07-08, files `SonyProtocolImplV2.java` and `SonyHeadphonesProtocol.java`. Pinned facts: the state is read and written through touch-sensor subtype `d1` with an inverted enable bit (`d6 d1` / `d7 d1 00 <00=on|01=off>` / `d8 d1 00 <00=on|01=off>`), a SET is followed by the fixed system-control apply commit `98 00 06 01` for both directions, and the system-control RET (`97 00 06 xx`) always reports `01` so it is never a state source. Gadgetbridge implements no v1 (WH-1000XM4) multipoint frames — `SonyProtocolImplV1.setConnectTwoDevices`/`getConnectTwoDevices` log "not implemented for V1" and return null — so no v1 fixture exists on purpose.

Both fixtures are deterministic and platform-independent. They use exact byte comparison; no scrubbing or tolerance is appropriate.
